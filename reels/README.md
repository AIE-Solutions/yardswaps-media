# Reels and Stories to Instagram and Facebook, plus TikTok

Free, automatic Reels for @yardswaps (Instagram) and the YardSwaps Facebook Page, posted by GitHub Actions (free for this public repo) through Meta's own API. No scheduler subscription, no Zapier tasks, nothing on anyone's computer.

## What it does
- Four Reels a day on each platform (raised from two on 2026-11-08): 7:00 am, 10:00 am, 4:30 pm and 6:30 pm Central, set in Central time (`SLOTS_CT` in `post_reels.py`), so daylight saving doesn't move them. HeyCatch posts at about :33 past 4 am, 12 pm and 8 pm Central (on Instagram and Facebook it also uses those same slots for its extra posts), and the Just listed photo post goes out at 2:15 pm, so each slot has a short window that keeps every post 90+ minutes clear of them: 7:00-9:30 am, 10:00-11:00 am, 4:30-6:00 pm, 6:30-7:00 pm. Before posting, the script also checks the last posts on each account and skips that slot if anything that isn't ours went up in the last 90 minutes. `slots` in `library.json` (e.g. `["07:00-09:30", "10:00-11:00"]`) changes the slots without touching code; fewer slots also lowers the daily cap.
- Picks the next video from `library.json`: videos never posted on that platform first (newest `added` first, then `priority`). Once every video has run, repeats go best performer first: each video's past Instagram Reels are scored by follows x10, shares x4, saves x3, comments x3, likes x1 (follows, shares and saves need the `instagram_manage_insights` permission; without it the score uses likes and comments). An optional `boost` number on a library entry adds to its score, so the weekly batch can push a cut that brought app signups. The same video never goes out twice on a platform within 10 days. On Instagram a repeat goes out as a Trial Reel (shown to non-followers first, shared to followers only if it does well), so followers don't see reruns.
- Uploads the file from `library/` directly, builds the caption and writes the result to `posted.json` (time, platform, video, post id, link).
- Safety cap: at most one of our Reels per slot (4) per platform in any 20 hours.
- Stories: right after each Reel, the same video goes to the @yardswaps Instagram Story and the YardSwaps Page Story (4 Stories a day on each, each live 24 hours). A Story re-shares the newest Reel from the last 24 hours that hasn't been a Story yet, so a skipped Reel slot means no Story that slot. Stories don't count toward the Reel cap or the 90-minute spacing, and a failed Story never fails the run (it shows as a warning and `failed` in `posted.json`). The API can't add link stickers or captions to Stories, so the link lives in the bio and in the Reel caption. Same token and permissions as Reels (`instagram_content_publish`, `pages_manage_posts`).

## Captions (built by `post_reels.py` from each video's `body`, `question`, `ig_tags`)
Goal: engagement, follows and app downloads. Every caption has the body, a follow line, the app link, hashtags, and ends with the open question.
- Instagram: body; "Follow @yardswaps for a new one every day. Get the free YardSwaps app: yardswaps.com/i (link in bio)."; up to 5 hashtags; the question.
- Facebook: body; "Follow the YardSwaps page for a new one every day. Get the free app and list it free: https://www.yardswaps.com/sell-equipment?utm_source=facebook&utm_medium=social&utm_campaign=reels_<slug>" (clickable, so it carries a per-Reel tag instead of the /f short link); its 2 machine hashtags plus #YardSwaps and the whole broad set (or `fb_tags` if set); the question.
- Hashtags: Instagram allows at most 5 per post since Dec 2025. Each Reel keeps the 2 machine/trade tags from its `ig_tags` (#forklift #forkliftforsale), always gets #UsedEquipment, and rotates 2 of the broad tags, moving 2 along every post: the jobsite tags Meta's Page assistant suggested on Nov 1 (#Jobsite #Tradespeople #IndustrialEquipment #EquipmentMarketplace #VerifiedSeller) plus the TikTok search terms from Nov 5 (#BlueCollar #ConstructionLife #SmallBusiness). TikTok uses `tt_tags()` in post_reels.py: 2 machine tags + #BlueCollar + #UsedEquipment + 1 of #ConstructionLife #SmallBusiness #BuildingThings #Jobsite (`tt_tags` in library.json overrides). When a video fits a TikTok search phrase ("pressure washer", "electrician work", "building things", "construction life", "small business", "blue collar"), the `body` opens with that phrase word for word, because TikTok search reads caption text, not only hashtags (CAPTIONS.md, Nov 5). `broad_tags` in `library.json` overrides the set; `ig_tags_fixed: true` on a video uses its `ig_tags` as written. #VerifiedSeller is accurate: the app gives sellers a Verified seller badge after a phone check.
- Backup runs: GitHub can start a scheduled run hours late or drop it (the Nov 1 4:30 pm run never started; the Nov 2 morning runs started about 9 hours late), so the workflow has 18 crons a day spread over the winter and summer slot times. Each run starts with a `gate` job that checks out only `post_reels.py`, `library.json` and `posted.json` and runs the script with `CHECK_ONLY=1`; the posting job (full checkout with the videos) only runs when a slot window is open and that slot hasn't posted yet, so most runs end in seconds. Both jobs check out the branch head, not the commit the run was queued at, so a run that waited behind another sees its log. A run that lands outside every window does nothing, so a late run never posts next to HeyCatch, and each slot posts once at most. Because GitHub's timer is this unreliable, a Claude scheduled task also starts the workflow at 7:42 am, 10:42 am, 4:42 pm and 6:42 pm Central every day; whichever run comes first posts and the rest stop.
- One-off posts: running the workflow by hand with `slug` set posts that video right away. It is logged with `forced: true`, so it doesn't use up one of the daily slots, and the 90-minute HeyCatch gap ignores our own posts.
- Queue order (Nov 1): Meta's Page assistant says jobsite-problem shorts (the proximity search one) reach 300+ views, so app-tool cuts that solve a jobsite hassle (find-it-nearby, spare-part, save-a-search, message-the-seller, make-an-offer) alternate with the idle-gear cuts that got good views. A new cut with a later `added` date still goes first. Nov 2: eight small-item / category-range cuts (micrometers, condenser, pressure washer, air movers, boring bars, truck wheel, chop saw, anchor adhesive) are spread through that queue about one a day instead of running back to back; they share the Nov 1 `added` date so `priority` sets the order.
- Location tag: Instagram Reels are tagged with a place from `locations` in `library.json`, one per day: Houston 3 days of every 7 (`weight`: 3), then Dallas, El Paso, San Antonio and Austin. An entry gives a Facebook place Page `id`, or a `wikidata` id whose Facebook Places ID (P1997) is looked up at run time; a city with no id falls back to Houston. A dry run lists the rotation and asks Meta what each id is. If Meta refuses an id, the Reel posts without a location. Stories can't take a location or hashtags through the API.
- Rules (CAPTIONS.md, ENGAGEMENT-PLAYBOOK.md, UTM-LINKS.md in the campaign folder): seller-first, the body says "Free to list" and "Free boosts", plain words, no emoji or icons, one open question about the viewer's own gear ending in "?", never promise views or sales, posted as the business. No #smallbusiness, #fyp, #reels, #explore.

## Adding new videos (weekly batch)
For each new 9:16 video with music:
1. Copy it to `reels/library/yardswaps-<slug>-9x16.mp4` (keep files under ~15 MB; Reels must be 3 to 60 seconds for Facebook).
2. Add an entry to `library.json`: `slug`, `file`, `priority` (0 = first), `added` (YYYY-MM-DD, today), `body` (seller text ending with a "Free to list ... Free boosts." line), `question` (from the comment prompt bank, not used before, ending in "?"), `ig_tags`, optional `boost` (adds to the repeat score), optional `hold: true` (+ `hold_reason`) to keep a video out of Reels, Stories and repeats until its cut is fixed. A fixed cut of an already-posted video goes in as a new slug with today's `added` date, so it posts at the next slot.
3. Commit to `main`. Newest `added` posts first.
Never delete `reels/` when clearing a week folder.

## Manual run
Actions tab > "Reels to Instagram and Facebook" > Run workflow. `dry_run` = 1 shows the pick and both captions without posting; `slug` forces a video; `platforms` takes any of `instagram,facebook,instagram_story,facebook_story` (Stories alone re-share the latest Reel).

## One-time setup (Alan, about 10 minutes, all free)
The workflow needs one Page access token, saved as the repo secret `META_PAGE_TOKEN`. Until it exists every run logs "not set yet" and posts nothing.
1. On the PC, in Chrome logged in to the Facebook account that manages the YardSwaps Page, open https://developers.facebook.com/apps and click **Create app** (accept the developer terms if asked).
2. Name `YardSwaps Reels`, contact email yardswaps@gmail.com. Use cases: tick **Manage everything on your Page** and **Manage messaging & content on Instagram** (if the screen instead asks for an app type, pick **Business**). Skip connecting a business portfolio. Create the app.
3. Open https://developers.facebook.com/tools/explorer/ . Meta App: **YardSwaps Reels**. Under Permissions add: `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, `instagram_basic`, `instagram_content_publish`, `instagram_manage_insights`, `business_management`. Click **Generate Access Token**, and in the Facebook window choose the YardSwaps Page and the @yardswaps Instagram account, then Continue/Save.
4. Back in the Explorer, in **User or Page** pick **YardSwaps** (the Page, not "Sunfire Corals"). The token box now holds a Page token.
5. Click the blue **i** next to the token > **Open in Access Token Tool** > **Extend Access Token** at the bottom. Copy the new token. (The token set on 2026-11-01 shows an expiry around Dec 31 2026, so it has to be renewed: see Renewal below.)
6. Open https://github.com/AIE-Solutions/yardswaps-media/settings/secrets/actions/new , Name `META_PAGE_TOKEN`, paste the token as the Secret, **Add secret**.
7. In the app's dashboard: App settings > Basic, Privacy Policy URL `https://www.yardswaps.com/privacy`, Category Business, Save. Then switch the app to **Live** (the "Publish" / App Mode toggle at the top) so posts are public.
Then tell the project thread "token added": it runs one test post to each platform.

## Scorecard (added 2026-11-03)
`metrics/` measures every Reel daily (`.github/workflows/metrics.yml`) and writes `metrics/rank.json`. Repeats now use it: the 3 best measured Reels get a boost, clear losers stop repeating ("retire"), and while the scorecard is fresh the hand-set `boost` numbers here are ignored unless the entry says `"boost_keep": true`. Each new slug also needs a row in `metrics/formats.json` (hook, angle, category). Details: `metrics/README.md`.

## TikTok
`.github/workflows/tiktok.yml` runs `post_tiktok.py` twice a day: 7:30 am and 5:30 pm Central in winter (8:30 am and 6:30 pm in summer), inside TikTok's morning and evening windows and 2+ hours clear of HeyCatch, which also posts to TikTok at about 4:30 am, 12:30 pm and 8:30 pm Central. If a manual run would land within 90 minutes of a HeyCatch slot, the script moves the Buffer publish time to 91 minutes after it. Same `library/`, same pick order, same 10-day no-repeat, at most 2 in 20 hours. Repeats are ranked by the video's Instagram engagement. If HeyCatch posts one of our library videos to TikTok, add `{"slug": "<slug>", "time": "<ISO time>"}` to `heycatch-tiktok.json` and it counts as posted for the 10-day rule. Log: `tiktok-posted.json` (each entry goes `scheduled`, then `posted` with the TikTok link on the next run; `unconfirmed` after 3 hours means look in Buffer for a failed post).

Caption: body; "Follow for a new one every day. Get the free YardSwaps app: yardswaps.com/t (link in bio)."; TikTok's own 5 hashtags from `tt_tags()` in `post_reels.py` (2 machine tags, #BlueCollar, #UsedEquipment, 1 rotating; a `tt_tags` entry in `library.json` overrides); the question. No @handle while the TikTok account is being renamed.

Why Buffer and not TikTok's own API: TikTok lets an unaudited app post only private ("only me") videos from a private account, and its guidelines say the audit is not granted for "a utility tool to help upload contents to the account(s) you or your team manages" (https://developers.tiktok.com/doc/content-sharing-guidelines). Buffer is an audited TikTok partner and its free plan includes the API (1 key, 1,000 requests per channel per 30 days; this uses about 150) and 10 queued posts per channel that refill as they publish (this keeps 1 queued at a time). Buffer only takes a public link, so the video is served from this public repo through jsDelivr at the exact commit.

### One-time setup (Alan, about 5 minutes, free, no card)
1. On the PC in Chrome, open https://buffer.com and click **Get started** / **Sign up**. Use yardswaps@gmail.com (Continue with Google is fine). If it offers a paid trial, choose the **Free** plan; never enter a card.
2. When it asks to connect a channel, pick **TikTok**, sign in to the YardSwaps TikTok account, and click **Authorize**. Connect only TikTok. If Buffer asks whether to publish automatically or send reminders, pick **automatic**.
3. In Buffer open **Settings**, then **API**, click **Create API key** (name it `YardSwaps TikTok`) and copy the key. Don't paste it anywhere except the next step.
4. Open https://github.com/AIE-Solutions/yardswaps-media/settings/secrets/actions/new , Name `BUFFER_API_KEY`, paste the key as the Secret, **Add secret**.
Then tell the project thread "Buffer key added": it runs the check (Actions > "Videos to TikTok" > Run workflow with `check` = 1) and one test post.

Manual run: Actions > "Videos to TikTok" > Run workflow. `dry_run` = 1 prints the pick, link and caption; `slug` forces a video; `check` = 1 only confirms the key and the TikTok channel.
